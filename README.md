# 웨이팅 순서 예측

현재 내 순서와 오늘의 도착시간으로 **입장 호출 시각의 확률분포**, 호출 유예를 넘길 위험, 최적 웨이팅 순서를 계산하는 한국어 정적 웹앱입니다. 킨카라멘과 다른 매장 탭을 제공합니다.

React 19 + TypeScript + Vite + Recharts를 유지했습니다. Web Worker에서 계산하며 서버·DB·환경변수·API 키가 필요하지 않습니다. 캐치테이블과 연동되지 않는 비공식 도구입니다. 실제 순서 변경은 사용자가 캐치테이블에서 직접 해야 합니다.

## 실행 및 검증

Node.js 22.12 이상:

```bash
npm ci
npm run dev
npm test
npm run typecheck
npm run lint
npm run build
npm run preview
```

`lint`는 충돌 마커·debugger·행 끝 공백을 검사하는 간단한 소스 검사입니다. ESLint 전체 규칙 검사를 수행하는 것은 아닙니다. 사용하지 않는 변수·타입 오류는 TypeScript가 검사합니다.

## 사용법

1. **킨카라멘**: 현재 내 순서와 도착시간을 입력합니다. 전체 대기 팀 수는 입력하지 않습니다.
2. 도착 후 허용 대기시간은 5/10/15분이며 기본값은 10분입니다. 입력 변경 시 자동 계산합니다.
3. 현재 순서의 호출 중앙값과 50/80/90% 예측구간을 확인합니다. 1번이 된 시각과 실제 호출은 다릅니다.
4. ‘도착할 때 바로 입장 가능’은 **도착 3분 전부터 도착 시각 사이의 호출**입니다. ‘도착까지 호출될 확률’은 너무 이른 호출도 포함하므로 같은 수치가 아닙니다.
5. 성공확률은 `P(도착−3분 ≤ 호출 ≤ 도착+허용 대기)`입니다. 그래프는 도착시간으로 호출을 잘라내지 않은 **무조건부 호출 분포**입니다.
6. 추천은 앞 순서를 포함한 이론상 최적 순서를 표시합니다. 앞으로 이동할 수 없으면 별도로 현재 순서 이상에서의 행동을 안내합니다. 실제 뒤쪽 순서가 존재하는지는 앱이 알 수 없으므로 캐치테이블에서 확인해야 합니다.
7. 비교 막대로 순서별 분포·누적 확률·조건부 도착 후 대기시간을 확인할 수 있습니다. 앞 순서 도달시간 목록도 유지했습니다.

현재 시각은 서울 기준으로 15초마다 확인하며, 분이 바뀌면 재계산합니다. 포커스 복귀·백그라운드 복귀 때도 재확인합니다. 실제 내 순서는 자동 수집하지 않습니다. 오래된 순서를 그대로 두면 ‘지금도 그 순서’라고 가정하므로 반드시 현황을 확인하세요. 과거 도착시간은 자동으로 다음 날로 바꾸지 않고 안내합니다.

‘13:06 실측 예시 보기’는 10/29 4번째 / 13:30 도착의 고정 시점 예시입니다. **예시 모드** 표시를 확인하고 실제 사용에는 ‘실시간으로’를 누르세요.

## 다른 매장

- 매장 이름은 선택입니다. **새 웨이팅**은 이전 세션을 보존하고 별도 세션을 만듭니다. 날짜·매장이 다른 자료를 합치지 않습니다.
- 관측 시각은 현재 시각으로 자동 입력되며 수정할 수 있습니다. ‘현재 시각으로’로 되돌릴 수 있습니다.
- 일반 관측 또는 **내가 직접 순서를 미룸**을 선택하고 미룬 후 순서를 입력합니다. 직접 미루기 직전~직후 구간은 속도 추정에서 제외합니다.
- 기록 수정·삭제가 가능하며 가장 최신 관측의 순서를 현재 순서 입력에 반영합니다. 같은 시각의 모호한 기록이나 설명되지 않은 순서 증가는 속도 추정에서 제외됩니다.
- 0~1개 기록은 킨카라멘 사전 모델을 그대로 사용하되 11시 영업 제한은 적용하지 않습니다. 2개 이상이면 `Gamma(λ₀×30 + 감소량, 30 + 관측분)`으로 해당 세션의 총 감소율을 갱신합니다.
- 관측 10분이면 실측 가중치 25%, 30분이면 50%, 60분이면 66.7%입니다. 취소·미루기는 이미 순서 감소에 포함되므로 다시 더하지 않습니다.
- 이전 방문을 선택해 내용을 볼 수 있습니다. 오늘 예측에 다른 날짜의 관측은 사용하지 않습니다. 새 방문에서는 새 웨이팅을 시작하세요.
- 킨카라멘의 **3분 유예와 호출/순서감소 속도의 관계를 다른 매장에서도 가정**합니다. 실제 매장 규칙과 다를 수 있습니다.

## 데이터와 모델

- `src/data/observations.json`: 10/29·10/30 원문 관측의 구조화 자료. Q, R, 메모, 모순 표시, 직접 미루기 구분을 보존합니다.
- 기존 `src/data/historicalWaiting.csv`의 54행은 10/29와 같은 방문입니다. 원본 보존용이며 신규 학습에서는 제외됩니다. 수정된 메모는 canonical JSON이 우선합니다.
- 유효 순서 관측 47구간, 223분, 총 72칸 감소. 단순 전체 평균 **3.097분/칸**입니다. 실제 입장 서비스 시간과는 다릅니다.
- 모델은 `Kᵢ ~ Poisson(Σ λ_b × 구간별 노출분)`의 구간 관측 likelihood를 사용합니다. 관측 종료 시점에 여러 이벤트가 동시에 발생했다고 가정하지 않습니다.
- 11~12시 / 12~13시 / 13시 이후의 세 구간과 약한 사전 정규화를 사용합니다. 직접 미루기·애매한 구간은 제외하고, Q 변화만으로 입장/취소를 확정하지 않습니다.
- 최종 계수와 사후분포 표본은 `src/data/fittedModel.json`에 고정합니다. 런타임에서는 킨카라멘 공식 계수를 변경하지 않습니다.
- 등록 10:30, 호출 11:00 이후. 누적 50팀 마감·조기 마감·추가 오픈은 관측 사실로 보존하며 고정 마감 시각이나 영구 등록 차단을 넣지 않습니다. 등록 상태 자체는 R-only 예측 입력이 아닙니다.

자세한 수식·계수·가정은 [MODEL.md](MODEL.md), 날짜별 검증 결과는 [VERIFICATION.md](VERIFICATION.md)를 참고하세요.

**현재 두 날짜의 교차검증에서는 정확도 향상이 확인되지 않았습니다.** 다음 순서 관측 MAE는 기존 0.8825칸, 새 모델 0.9189칸입니다. 실제 호출 완료 시각이 없어 호출시간 MAE와 입장 성공확률 보정은 검증할 수 없습니다. 이 사실을 숨기고 ‘고정밀’로 소개하지 않습니다.

## 개발 시에만 계수 재추정

```bash
npm run fit-model       # canonical 관측 -> 고정 JSON
npm run validate-model  # 날짜별 holdout 검증 -> docs/validation-results.json
npm run analyze         # 두 명령 순차 실행
```

CSV나 기록을 수정하기만 해서는 배포 모델이 바뀌지 않습니다. 개발자가 canonical 데이터를 검토하고 위 명령과 테스트를 실행한 뒤 변경 파일을 커밋해야 합니다. 브라우저 실측은 이 과정이나 GitHub로 자동 전송되지 않습니다.

## 브라우저 저장

`localStorage`의 `waiting-order-prediction`, `schemaVersion: 1`에 탭, 입력, 활성 세션, 모든 방문 기록을 저장합니다. 새로고침·종료 후에도 브라우저가 허용하는 범위에서 유지합니다. 전체 초기화와 세션 초기화를 제공합니다. 저장 제한·용량 초과·손상·알 수 없는 미래 버전은 앱을 멈추지 않고 안내하며, 알 수 없는 저장 형식은 자동으로 덮어쓰지 않습니다.

서버 업로드·사용 이력 수집·자동 GitHub 업데이트·영구 모델 학습은 없습니다. 사설 모드나 브라우저 정리로 기록이 삭제될 수 있어 **영구 보관을 보장하지 않습니다**. 여러 탭에서 동시에 편집하는 경우 마지막 저장이 우선합니다.

## 배포

기존 저장소 이름과 `netlify.toml`, `vercel.json`, Vite 배포 경로를 유지했습니다.

- Netlify: GitHub `main` 연동, Build `npm run build`, Publish `dist`, Node 22.
- Vercel: Vite, 동일 빌드·출력 경로. 환경변수 없음.
- 별도 서버·Function은 없습니다. HTTP/HTTPS 서버로 제공해야 ES 모듈과 Worker가 작동합니다.
- 루트 배포가 기본입니다. 서브경로 배포에는 Vite `base`를 맞춰야 합니다.
- `python3 scripts/package-source.py`로 소스 ZIP을 재생성한 다음 빌드하면 기존 다운로드 기능도 갱신됩니다.

## 주요 파일

```text
src/models/observations.ts       # 구간 구성·중복·직접 미루기 처리
src/models/fitting.ts            # 구간 likelihood / 사후표본
src/models/simulation.ts         # 순서 감소 + 별도 호출 대기
src/models/optimizer.ts          # 도착/유예 기반 최적 후보
src/state/storage.ts             # 저장 스키마·세션 연산
src/components/StoreSession.tsx  # 실측 입력·수정·삭제
src/data/fittedModel.json        # 고정 배포 계수
scripts/validate-model.ts        # 날짜 교차검증
scripts/legacy/                  # 기존 모델 보존, 개발 비교 전용
```

라이브러리는 기존 의존성을 재사용하며 신규 무거운 패키지를 추가하지 않았습니다.
