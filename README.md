# 웨이팅 순서 예측

현재 내 순서와 도착시간을 입력하고 예측하기를 누르면 예상 호출시간과 최적 순서를 계산하는 정적 웹앱입니다. 기존 React·TypeScript·Vite·Recharts 구성과 Netlify 설정을 유지합니다.

## 사용법
- **킨카라멘**: 10/29·10/30 관측으로 갱신한 고정 계수를 사용합니다.
- **다른 매장**: 예측하기를 누르면 현재 시각과 순서를 계산에 반영하고, 완료 시 자동 기록합니다. 기록은 직접 추가·수정할 수 없고 삭제·초기화만 가능합니다. 같은 분·같은 순서의 연속 예측은 중복 저장하지 않습니다.
- 이전보다 순서 숫자가 커지면 미루기로 판단해 해당 기록 이전 구간을 속도 계산에서 제외합니다. 다른 매장으로 옮기거나 새로 방문하면 기록을 초기화하세요.
- 입력 변경·시간 경과·탭 전환·기록 삭제·새로고침 시 자동 계산하지 않습니다. 예측하기를 눌러 갱신하세요. 결과에는 비교 순서의 평균 감소 시간과 한 팀당 10분 내 취소·미루기 확률, 사용 계수·계산식을 표시합니다.
- 오늘 기록 0~1개는 킨카라멘 기준, 2개부터는 해당 매장 기록만으로 호출 속도를 추정합니다. 킨카라멘 호출 속도와 30분 보정은 사용하지 않으며 취소·미루기 확률은 고정값을 유지합니다. 같은 분·미루기 기록만으로 유효 구간이 없으면 기록을 저장하고 다음 관측을 기다립니다. 새 방문에서는 기록을 초기화하세요.
- 최적 순서는 앞 순서까지 비교합니다. 앞으로 당길 수 없는 경우 이를 표시하며 실제 미룰 수 있는 순서는 캐치테이블에서 확인해야 합니다.
- 도착 3분 전~도착 후 허용 대기 5/10/15분 사이 호출될 확률을 최대화합니다.

입력과 기록은 버전이 있는 localStorage에 저장합니다. 새로고침 후 복원되지만 브라우저 데이터 삭제·저장 차단 등으로 유실될 수 있습니다. 서버 전송, 공식 계수 자동 변경, GitHub 자동 업데이트는 없습니다. 킨카라멘과 다른 매장 입력은 분리됩니다. 다른 날짜 기록은 보관만 하고 오늘 추정에서 제외합니다.

## 개발·검증
Node.js 22.12 이상. `npm ci`, `npm run dev`로 실행합니다.

```sh
npm test
npm run typecheck
npm run fit-model
npm run validate-model
npm run build
```

`src/data/observations.json`이 두 날짜의 정규화된 원자료입니다. 기존 `historicalWaiting.csv`는 같은 10/29 방문이므로 중복 학습하지 않습니다. 계수 변경은 개발자가 fit-model을 실행하고 검토·커밋한 경우만 배포됩니다. 로컬 매장 기록은 해당 브라우저의 예측에만 사용됩니다.

Netlify: `npm run build`, 출력 `dist`, Node 22. 기존 `netlify.toml`·`vercel.json` 유지. 별도 서버·환경변수·API 키가 필요하지 않습니다. 소스 ZIP 갱신은 `python3 scripts/package-source.py`입니다.
